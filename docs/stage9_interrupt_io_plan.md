# 阶段9：键盘输入与中断 I/O 实现计划

## 1. 推荐实现目标

本阶段推荐实现“PS/2 键盘输入 + 内存映射 I/O + 中断通知”。

该方案同时覆盖阶段9要求中的：

- 中断机制
- 输入输出系统
- 键盘接口

实现完成后，键盘按下按键时，PS/2 控制器接收扫描码并生成键值；键值写入 I/O 寄存器；设备向 CPU 发出中断请求；CPU 进入中断处理程序读取键值并清除中断。

## 2. 为什么选择这个方案

相比 VGA 或字符输入界面，键盘中断 I/O 更适合作为当前 CPU 项目的下一步。

优点：

- 和 CPU 系统结合紧密，不只是独立外设演示。
- 模块规模可控，可以先实现轮询 I/O，再扩展为中断。
- 面试时容易讲清楚：外设控制器、状态寄存器、数据寄存器、中断请求、异常入口、返回机制。
- 后续可以继续扩展到字符输入界面或 VGA 输出，不会浪费已有工作。

风险：

- 需要修改 CPU 控制流，增加中断响应路径。
- 需要定义清楚 I/O 地址、中断入口、清除中断方式。
- 如果直接上板验证，PS/2 时序和引脚约束需要单独调试。

## 3. 总体架构

建议采用如下结构：

```text
PS/2 keyboard
    |
    v
ps2_keyboard 接收控制器
    |
    v
keyboard_io 外设寄存器
    |              |
    |              +--> irq
    v
memory mapped I/O
    |
    v
CPU load/store 访问
```

CPU 通过普通 `lw` / `sw` 指令访问 I/O 地址。键盘设备通过 `irq` 信号通知 CPU 有新输入。

## 4. 模块划分

### 4.1 PS/2 接收模块

职责：

- 同步外部 `ps2_clk`。
- 检测 `ps2_clk` 下降沿。
- 按 11 位 PS/2 帧接收数据。
- 输出 8 位扫描码。
- 提供 `ready` 标志。

可参考课程实验七中的 `ps2_keyboard` 模块。

### 4.2 扫描码解析模块

职责：

- 区分通码和断码。
- 忽略 `F0` 释放前缀。
- 可选处理 `E0` 扩展前缀。
- 将常用按键扫描码映射为 ASCII 或内部键值。

第一版建议只支持：

- 数字 `0` 到 `9`
- 字母 `A` 到 `Z`
- 空格
- 回车
- 退格

### 4.3 键盘 I/O 寄存器模块

建议定义两个寄存器：

| 地址 | 名称 | 读写 | 说明 |
|---|---|---|---|
| `0xFFFF0000` | `KBD_DATA` | R | 最新键值，低 8 位有效 |
| `0xFFFF0004` | `KBD_STATUS` | R/W | bit0 表示 ready，写 1 清除 ready/irq |

行为：

- 有新键值时，`KBD_DATA` 更新，`KBD_STATUS[0]` 置 1。
- `KBD_STATUS[0] == 1` 时拉高 `irq`。
- CPU 读取 `KBD_DATA` 后，可以通过向 `KBD_STATUS` 写 1 清除状态。

### 4.4 CPU 中断机制

第一版建议实现最小中断机制，而不是完整 RISC-V 特权级 CSR。

需要增加：

- `irq` 输入。
- `in_interrupt` 状态位，避免重复进入中断。
- `epc` 寄存器，保存被打断时的下一条 PC。
- 固定中断入口地址，例如 `0x00000100`。
- 一条自定义返回机制，或用约定的特殊指令返回。

建议的最小行为：

```text
if irq && !in_interrupt:
    epc <= next_pc
    pc  <= 0x00000100
    in_interrupt <= 1
```

中断处理程序完成后，执行返回操作：

```text
pc <= epc
in_interrupt <= 0
```

如果不想增加新指令，可以先用一个特殊 I/O 写操作触发中断返回，但面试时需要说明这是课程项目中的简化设计。

### 4.5 数据存储器与 I/O 地址译码

当前 CPU 的 `lw` / `sw` 访问需要区分普通数据存储器和 I/O 外设。

建议：

- 地址落在 `0xFFFF0000` 附近时访问 I/O。
- 其他地址仍访问原 `dm.v`。
- 读 I/O 时返回外设寄存器数据。
- 写 I/O 时生成外设写使能。

## 5. 实施顺序

建议分三步推进，每一步都能单独验证。

### 第一步：实现轮询式键盘 I/O

目标：

- CPU 可以通过 `lw KBD_STATUS` 查询是否有按键。
- 有键值时，通过 `lw KBD_DATA` 读取。
- 暂时不接中断。

验收：

- 仿真中模拟键盘输入，观察 I/O 寄存器变化。
- 程序能读到键值并存入普通内存或寄存器。

### 第二步：加入中断请求

目标：

- 键盘 ready 时产生 `irq`。
- CPU 响应 `irq`，跳转到固定中断入口。
- 保存返回地址到 `epc`。

验收：

- 仿真中主程序正常运行。
- 产生键盘输入后，PC 跳转到 `0x00000100`。
- 中断处理程序读取键值并清除 ready。

### 第三步：实现中断返回

目标：

- 中断处理结束后回到主程序。
- `in_interrupt` 清零。
- 后续按键仍能再次触发中断。

验收：

- 连续输入多个键值，CPU 可以多次进入和退出中断。
- 不出现中断嵌套导致的 PC 错乱。

## 6. 测试计划

### 6.1 模块级测试

测试对象：

- PS/2 接收模块
- 扫描码解析模块
- 键盘 I/O 寄存器模块

重点检查：

- `F0` 断码不会被当成有效字符。
- 连续按键不会丢失 ready 状态。
- 清除 ready 后 `irq` 会下降。

### 6.2 CPU 集成测试

测试场景：

- 无按键时，主程序正常执行。
- 有按键时，CPU 跳转到中断入口。
- 中断程序读取键值。
- 清除中断后返回主程序。

建议在 `results.txt` 或波形中观察：

- `PC`
- `irq`
- `in_interrupt`
- `epc`
- I/O 读写地址
- 键值数据

### 6.3 上板测试

如果需要上板：

- 接入 PS/2 引脚约束。
- 使用数码管或 LED 显示最近按键扫描码/ASCII。
- 用一个 LED 显示 `irq` 或 `ready` 状态。

## 7. 面试讲解重点

可以按以下顺序讲：

1. 输入输出系统为什么不能只靠普通内存。
2. 为什么使用内存映射 I/O。
3. 键盘控制器如何把串行 PS/2 信号变成并行扫描码。
4. 状态寄存器和数据寄存器如何暴露给 CPU。
5. 轮询和中断的区别。
6. 中断响应时 CPU 保存什么、跳到哪里、如何返回。
7. 本项目为什么采用简化中断机制，而不是完整 RISC-V 特权级 CSR。

## 8. 可裁剪方案

如果时间紧：

- 只做轮询式键盘 I/O，也能满足输入输出系统。
- 再用 `irq` 信号和固定入口补上最小中断。
- 暂不支持 Shift、大写转换和复杂扩展键。

如果时间充足：

- 支持完整 ASCII 映射。
- 增加小 FIFO，避免连续按键丢失。
- 接 VGA 或字符显示界面，做成简单终端。
- 将中断机制升级为更接近 RISC-V 的 `mepc` / `mtvec` / `mret` 风格。

## 9. 初步文件改动预估

- `sccomp_tb.v`：增加键盘输入和中断集成仿真。

## 10. 推荐结论

阶段9建议先实现“键盘 I/O 寄存器 + 轮询读取”，验证通过后再加入“键盘 ready 触发 CPU 中断”。

这样路线稳，验收容易拆分，面试时也能自然覆盖输入输出系统和中断机制两部分内容。

## 11. 当前实现记录

根据 Vivado 工程当前已经纳入的源文件，第一版实现选择把键盘相关辅助模块放在 `fpga_top.v` 内，避免新增 Verilog 文件后忘记加入 Vivado 工程。

实际 I/O 地址如下：

| 地址 | 名称 | 说明 |
|---|---|---|
| `0xFFFF0004` | `SWITCH` | 原有拨码开关输入 |
| `0xFFFF000C` | `SEG7_DATA` | 原有数码管显示寄存器 |
| `0xFFFF0010` | `KBD_DATA` | 键盘 ASCII 数据，低 8 位有效 |
| `0xFFFF0014` | `KBD_STATUS` | bit0 为 ready/irq，bit1 为 interrupt_active，bits[15:8] 为最近扫描码；写 bit0 清 ready |
| `0xFFFF0018` | `IRQ_RET` | 中断处理程序写 1 后返回 `epc` |

当前下板演示程序已写入 `riscv-studentnosorting.coe`，中断入口固定为 `0x00000100`。按下键盘后，CPU 进入中断处理程序，读取 `KBD_DATA`，写入 `SEG7_DATA`，清除 `KBD_STATUS`，最后写 `IRQ_RET` 返回主程序。

上板时建议让 `sw_i[15] = 0`，保持 CPU 使用较快时钟；`sw_i[2:0] = 000` 时数码管显示程序写入的最近键值，`sw_i[2:0] = 111` 时显示键盘调试状态。

已完成的本地验证：

- 原 `run_sim.ps1` 可以正常编译并运行，说明新增中断端口没有破坏原仿真顶层。
- 使用临时顶层仿真模拟 PS/2 `A` 键扫描码 `0x1C`，CPU 进入 `0x00000100` 中断入口后把数码管寄存器写为 `0x00000041`，随后返回主循环。
